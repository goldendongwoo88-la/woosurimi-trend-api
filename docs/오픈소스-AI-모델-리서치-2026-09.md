## 1. 영상 제작 (Text/Image → Video)

### 1-1. LTX-2.5 — 지금 시점 오픈 영상 모델의 최상위 ⭐

| 항목 | 내용 |
|---|---|
| 만든 곳 | Lightricks (이스라엘, Facetune 만든 회사) |
| 공개일 | **2026년 8월 11일** ✅ |
| 크기 | 22B 파라미터 |
| 라이선스 | **연매출 1,000만 달러 미만이면 무료** (학술·상업 모두). 브랜딩 표기 의무 없음 ✅ |
| 특징 | **영상과 소리를 한 번에 생성** (입모양 동기화 포함), 4K HDR, 멀티샷 장면, 자동 길이 |
| 속도 | GB200 2장에서 10초 720p 영상을 6.8초에 (일반 그래픽카드는 훨씬 느림) |
| ComfyUI | **출시 당일 공식 지원**, 워크플로 템플릿 제공 ✅ |

**왜 1순위인가**: 오픈 모델 중 **소리까지 같이 나오는 건 LTX 계열이 유일**합니다. 숏폼은 소리가
절반인데, 다른 모델은 영상만 뽑고 소리를 따로 붙여야 합니다. 계보는 LTX-2(2025년 10월) →
LTX-2.3(2026년 3월) → LTX-2.5(2026년 8월)입니다.

**주의**: 연매출 1,000만 달러(약 140억 원)를 넘으면 별도 상업 라이선스가 필요합니다.
사장님 규모에서는 문제없습니다.

### 1-2. Wan 2.2 — "확실하게 받을 수 있는" 안전빵 ⭐

| 항목 | 내용 |
|---|---|
| 만든 곳 | Alibaba 통이랩 |
| 라이선스 | **Apache-2.0** ✅ (상업적 사용·수정·재배포 전부 자유) |
| 종류 | T2V-A14B(글→영상), I2V-A14B(사진→영상), **TI2V-5B**(경량) |
| VRAM | 5B GGUF + 오프로딩으로 **8GB부터** ✅ / 14B는 FP8로 16GB 이상 |
| 속도 개선 | **Wan2.2-Lightning** LoRA를 얹으면 **4스텝**만에 생성 (약 20배 빨라짐) ✅ |

**8GB 그래픽카드 설정** (검색으로 확인된 실전 값):
- 5B 모델의 `Q3_K_S` 또는 `Q3_K_M` GGUF 양자화본 사용
- 텍스트 인코더는 CPU에 올려두기
- `wan2.2_t2v_lightx2v_4steps_lora_v1.1_high_noise.safetensors` + `low_noise` 두 개를 LoRA로 적용

### 1-3. ⚠️ Wan 2.5 / 2.6 / 2.7 / 3.0 — 여기가 함정입니다

검색 결과가 **정면으로 충돌**합니다. 정리하면:

- **Wan 2.6** (2025년 12월): 여러 출처가 **API 전용, 가중치 비공개**라고 말함
- **Wan 2.7** (2026년 4월, 27B MoE): 어떤 출처는 "Apache-2.0 오픈 가중치", 다른 출처는
  "가중치 미공개, API 전용" ⚠️ **완전히 충돌**
- 한 출처는 "2.5, 2.6, 2.7, 3.0 네 세대 연속으로 비공개라 커뮤니티 반발이 있었고,
  이후 일부 모델만 Apache-2.0으로 풀렸다"고 서술

**저의 판단**: Wan 계열은 **버전마다 오픈/클로즈를 오갔습니다.** 그래서 "Wan 2.7이 최신이니
그걸 쓰자"고 계획을 세우면 안 됩니다. **지금 확실하게 내려받아 상업적으로 쓸 수 있는 건
Wan 2.2까지**입니다. 2.7을 쓰시려면 Hugging Face의 `Wan-AI` 조직 페이지를 직접 확인하세요.

### 1-4. HunyuanVideo 1.5 (Tencent) — ⚠️ 라이선스 확인 필수

- 8.3B 파라미터, FP8 + CPU 오프로딩으로 **약 14GB**, GGUF는 8~12GB ✅
- ⚠️ **라이선스 충돌**: "Tencent Hunyuan Community License(연구·개인용, 상업 제한)"라는 출처와
  "Apache 2.0으로 상업 무료"라는 출처가 동시에 나옵니다. **상업적으로 쓰실 거면 반드시 원문 확인.**

### 1-5. 그 외

- **CogVideoX-5B**: 프롬프트 이해력(여러 조건이 붙은 복잡한 문장)에서 강점 ❓
- **Mochi-1** (Genmo): 10B, Apache-2.0, 동작 표현 특화. 다만 2024년 모델이라 지금은 구세대

## 2. 영상 편집

### 2-1. Wan-VACE — 편집 통합 모델 ⭐

Alibaba 통이랩이 만든 **"영상 편집 올인원"** 모델입니다. 하나의 모델로 전부 처리합니다:

| 기능 | 설명 | 우리 쓰임새 |
|---|---|---|
| R2V (참조→영상) | 참조 이미지의 인물·사물을 그대로 영상에 등장시킴 | 사주 캐릭터 일관성 |
| V2V (영상→영상) | 기존 영상에 스타일 입히기, 포즈/뎁스 제어 | 롱폼 → 숏폼 톤 통일 |
| MV2V (마스크 편집) | 특정 영역만 **인페인팅/아웃페인팅** = 지우기, 채우기, 화면 넓히기 | 워터마크·로고 제거, 세로 화면 확장 |

ComfyUI에 `WanVaceToVideo`, `TrimVideoLatent` 노드로 **네이티브 지원**됩니다 ✅.
`ComfyUI-Wan-VACE-Prep` 커스텀 노드를 쓰면 전환·연장·아웃페인팅이 더 쉬워집니다.

> **지금 프로젝트와의 연결**: `shortsStudio.js`가 지금은 "피사체 위치로 잘라내는" 방식으로
> 가로 영상을 세로로 만듭니다. VACE 아웃페인팅을 쓰면 **잘라내는 대신 좌우를 AI가 그려서
> 채우는** 방식이 가능합니다. 다만 GPU가 필요해서 Render 서버에서는 못 돌리고 로컬 전용입니다.

## 3. AI 얼굴 학습 (인물 일관성)

목표는 두 가지로 갈립니다. **① 매번 같은 얼굴이 나오게 하기**(캐릭터 브랜딩) /

### 3-1. 학습형 — 얼굴 LoRA 만들기 ⭐ (품질 최상위)

### 4-3. ⭐ 가장 중요한 결론 — 한글은 AI에게 맡기지 마세요

**질문**: 오픈소스 이미지 모델이 카드뉴스용 한글을 제대로 써주는가?
**답**: **아직 아닙니다. 그리고 사장님은 이미 더 좋은 방법을 쓰고 계십니다.**

근거:
- Qwen-Image는 "영어·중국어·**한국어**·일본어 고정밀 텍스트 생성"을 공식적으로 표방합니다.
- 그런데 **한국어 원어민이 데모를 한 글자씩 검수했더니 실제 오류**가 나왔습니다 —
  모음이 뒤바뀌고, 여러 단어가 틀리게 나왔습니다. "12개 언어 네이티브 지원" 같은 홍보 문구를
  원어민 검수 없이 믿으면 안 된다는 경고까지 붙어 있습니다.
- 2026년 4월 OpenAI가 "이미지 2.0"에서 한글 깨짐을 드디어 해결했다고 국내 언론이 보도했는데,
  이건 **클로즈드 모델**입니다. 오픈 진영은 아직 그 수준이 아닙니다.

**그래서 지금 `cardNewsGenerator.js`가 하고 있는 방식이 정답입니다.**

> fontkit으로 NotoSansKR-Bold.ttf의 **글자 윤곽선을 SVG path로 직접 추출**해서 sharp로
> 그리는 방식 — 시스템 폰트·fontconfig에 전혀 의존하지 않고, **오타가 원천적으로 불가능**하며,
> Render 리눅스 서버에서도 로컬과 똑같이 나옵니다.

AI 이미지 모델은 **글자 없는 배경**만 만들게 하고, 글자는 지금처럼 코드로 얹으세요.
이게 품질·정확도·비용 모든 면에서 우위입니다. 바꾸지 마세요.
