## 1. 영상이 만든 것 — 그대로 따라 할 수 있는 수준으로

영상은 1부(코워크)와 2부(n8n)로 나뉜다. **핵심은 1부다. 2부는 1부를 시간에 맞춰 깨우는 것뿐이다.**

### 1부 — 클로드 코워크 안에 "AI 편집팀" 만들기

**준비**
1. 클로드 **코워크** 열기 → `새 작업`
2. 작업할 **빈 폴더** 하나 만들고 그 폴더를 선택 → 권한 창은 `항상 허용`
3. 지침에 안전장치 한 줄: **"파일 삭제하기 전에는 꼭 확인해 줘."**
   (코워크는 내 컴퓨터 파일을 직접 만지므로 이 한 줄이 브레이크다)

**팀 구성 — 팀장 1 + 팀원 4.** 팀원 하나 = 마크다운 지침 파일 하나다.

| 순서 | 파일 | 하는 일 | 넣은 조건 |
|---|---|---|---|
| ① | 스타일 가이드 | 내 말투 | 예전 내 글 2~3편을 통째로 올리고 "말투 특징 정리해 줘" → 문장 길이·자주 쓰는 표현·시작/마무리 방식이 나온다. 마음에 안 드는 표현은 "이건 빼 줘"로 즉시 수정 |
| ② | 검색 규칙 | SEO/AEO/GEO | 클로드가 웹에서 찾아 정리 → 제목 글자 수·본문 분량·키워드 위치. **규칙이 바뀌면 이 파일만 다시 만들면 결과물이 같이 바뀐다.** 티스토리면 "티스토리 기준으로 바꿔 줘" |
| ③ | 리서치 팀원 | 자료 조사 | (a) 큰 주제를 받으면 사람들이 실제로 검색하는 **세부 키워드**를 직접 찾을 것 (b) 검색은 되는데 **경쟁이 약한** 키워드를 우선순위로 뽑을 것 (c) 그 키워드 정보를 정리할 것 — **+ 확인 안 된 내용은 쓰지 말고, 자료마다 출처를 붙일 것** |
| ④ | 글쓰기 팀원 | 원고 | ①②③ **세 파일을 다 읽고** 반영해 작성. 말투·검색 규칙은 반드시 지키고, 리서치 내용 중심으로 쓰되 자연스럽게 이어지는 부분은 알아서 채워도 됨. **이미지 들어갈 자리는 표시만** |
| ⑤ | 이미지 팀원 | 삽화 | 표시된 자리마다 어울리는 **슬라이드**를 만들고 이미지 파일로 저장. **만든 뒤 스스로 다시 확인** — 글자가 잘렸거나 여백이 이상하면 문제없을 때까지 알아서 재생성 |
| ⑥ | 조립 팀원 | 완성 | 이미지 자리에 실제 이미지를 넣고 블로그에 바로 쓸 수 있는 형태로 |
| ⑦ | **팀장** | 지휘 | 지금 뭘 만드는지 / 팀원 파일이 어디 있는지 / 순서 / 진행할 때마다 "지금 몇 번째 팀원이 일하는 중"을 한 줄로 보고. **팀장은 직접 쓰거나 그리지 않고 시키기만 한다** |

**영상이 강조한 설계 판단 두 개 — 여기가 진짜 알맹이다.**

- **왜 한 번에 안 시키고 쪼개나**
  > 한 번에 다 시키면 앞뒤 얘기가 섞여서 결과물이 들쑥날쑥해진다. 역할을 나누면 **문제 생긴 팀원만 다시 시키면 된다.**

- **왜 팀장을 맨 마지막에 만드나**
  > 팀장을 먼저 만들어 두면 팀원을 하나 고칠 때마다 팀장 내용도 같이 고쳐야 해서 지저분해진다.

**이미지 방식이 영리하다.** 그림을 그리는 게 아니라 **깔끔한 슬라이드를 만들어 이미지로 변환**한다.
그래서 글자가 잘리거나 어색해지지 않는다. 게다가 자가 검수 루프(잘림·여백 확인 → 재생성)까지 붙였다.

### 2부 — n8n으로 무인화 + 개선 루프

**워크플로우 3개**를 임포트하고 스케줄만 켠다.

1. **글 생성** — 정해진 시각에 클로드를 깨움 → `topics.md`에서 한 줄 꺼냄 → 리서치 → 원고 → 이미지 → **네이버 에디터 스키마 그대로 HTML 조립**
2. **에디터 투입** — 크롬을 열어 에디터 안에 문단을 하나씩 심고 **임시저장**까지
3. **주간 개선** — 유입 데이터를 보고 프롬프트를 고침

**투입구는 `topics.md` 파일 하나다.** 그날 쓰고 싶은 인사이트를 **한 줄** 적어 둔다.
(예: "프롬프트를 이렇게 주었더니 성능이 올랐다")
→ 다음 날 아침 완성된 글이 **네이버 임시저장함**에 들어가 있다.

> **발행 버튼은 사람이 누른다.** 영상 표현: "네이버는 조심해야 될 부분이 좀 있어서, 임시저장까지만 자동으로 하고 최종 발행 버튼은 검수하고 직접 누르는 걸로."

**영상이 "오늘 당장 쓸 수 있는 꿀팁"으로 꼽은 것 (도구 없이 되는 것)**
> 네이버 블로그 **통계(유입 검색어·조회수)를 그대로 클로드에 붙여넣고** 물어보면
> 저조한 원인 → 다음 글 방향 → **프롬프트 수정안**까지 한 번에 나온다. 주 1회만 해도 글 퀄리티가 달라진다.

### 영상을 읽을 때 감안할 것

- 영상 마지막은 **자동화 컨설팅 영업**이다(무료 컨설팅 링크, 고정 댓글).
- 성과 증거는 "지난주 발행 7편" 화면 하나뿐이다. **유입·수익 숫자는 나오지 않는다.**
  즉 "이 시스템이 성과를 냈다"는 검증은 영상에 없다. 구조는 배울 값이 있고, 실적 주장은 근거가 없다.

**확인된 공백 두 개**

1. **임시저장 마지막 1cm** — 확장에 `saveDraft()`도 있고 무인 모드 결과 보고선도 있다.
   막힌 지점이 명확하다: 퍼펫티어가 `chrome.debugger`를 점유해 **확장의 진짜 붙여넣기 경로를 막는다.**

   `schedule.js`가 발행 시각을 배정하지만 **그 시각에 아무도 깨우지 않는다.**

## 4. 어느 쪽이 더 효율적인가 — 결론

**층을 나눠서 봐야 한다.**

```
[품질 층]  무엇을 쓸지 · 어떻게 쓸지 · 통과 기준     →  우리가 영상보다 한참 앞서 있다
[연결 층]  누가 언제 깨우고 · 어디에 넣고 · 실패하면  →  영상이 앞서 있다. 우리는 비어 있다
```

- **품질 층**: 영상은 "AI야, SEO 규칙 좀 찾아서 정리해 줘"다. 우리는 **홈판을 직접 재서 나온 숫자**를 코드 상수로 박아 뒀고, 통과 여부를 AI가 아니라 코드가 판정한다. 이건 격이 다르다.
  영상 방식대로 하면 규칙이 매번 조금씩 달라진다. 우리는 안 달라진다.
- **연결 층**: 영상은 `topics.md`에 한 줄 → 다음 날 아침 임시저장함. 우리는 **사장님이 모든 단계를 클릭해야** 한다.

**그래서 답은 "영상 방식으로 갈아탄다"가 아니라 "우리 품질 층 위에 연결 층 하나만 얹는다"다.**
갈아타면 3·4번(우리 압도)을 버리고 8·9번(격차 2개)을 사는 셈이다. 명백한 손해다.

## 5. n8n을 도입해야 하나 — **지금은 아니다**

n8n이 파는 것은 넷이다. 우리 기준으로 하나씩 값을 매기면:

| n8n이 주는 것 | 우리에게 값이 있나 |
|---|---|
| ① 크론(정시 실행) | **없음.** 윈도우 작업 스케줄러가 이미 `GwBackupEvery2h`로 검증됐다. `node scripts/xxx.js` 한 줄 등록이면 끝 |
| ② 노드 GUI | **마이너스.** 우리 로직은 이미 코드에 있다. 절반을 노드로 옮기면 **로직이 두 군데로 쪼개진다** — 버그 나면 어디를 봐야 하는지부터 헷갈린다 |
| ③ 커넥터 400+ | **없음.** 네이버는 커넥터가 없다(그래서 영상도 크롬을 직접 연다). 편집국은 로컬 HTTP 한 줄. 클로드는 이미 SDK |
| ④ 실행이력·재시도·실패알림 | **있음. 이것만 진짜 없다.** 그런데 러너 스크립트 하나(50줄)면 된다 |

**요약: 서버를 10번째로 하나 더 띄우고 로직을 쪼개는 값을 치르고, 얻는 건 ④ 하나다. 지금은 안 산다.**

**재검토 조건 (이때는 n8n이 값을 한다)**
- 이 자동화를 **크몽·컨설팅 상품으로 남에게 넘길 때.** 코드를 못 읽는 사람이 화면으로 보고 고쳐야 하면 GUI가 값을 한다.
  (영상 화자의 목적도 결국 이것이다 — 컨설팅 영업)
- 외부 SaaS를 5개 이상 엮게 될 때 (슬랙·노션·구글시트·메일 동시)

## 6. 영상에서 가져올 것 / 절대 가져오지 말 것

### 가져올 것 3개

1. **`topics.md` 한 줄 인박스** ★
   우리는 소재를 RSS로 자동 수집한다. 좋다. 그런데 **사장님 머릿속의 "오늘은 이걸 쓰고 싶다"를 넣을 자리가 없다.**
   한 줄 인박스가 있으면 자동화가 사장님 의도를 태우고 돈다. 이게 영상 구조의 진짜 발명이다.

2. **네이버 블로그 통계 → 프롬프트 개선 루프** ★★
   **이게 미수확 중 제일 크다.** `gw_analytics_2026`은 이미 배율표·A/B·TOP훅 그릇을 갖췄는데
   **블로그 통계(유입 검색어·조회수)가 안 들어가 있다.** 주 1회 붙여넣기만 해도 루프가 돈다.
   도구도 필요 없다. 오늘 당장 된다.

3. **이미지 자가검수 루프**
   슬라이드 만든 뒤 **스스로** 글자 잘림·여백을 확인하고 문제없을 때까지 재생성. 썸네일 메이커에 붙일 값이 있다.

### 가져오지 말 것

- **"AI가 SEO 규칙을 웹에서 찾아 만들게 하기"** — 우리는 홈판 실측치가 있다. 이걸 AI 생성 가이드로 바꾸면 **명백한 다운그레이드**다.
- **n8n으로 로직 이전** — 위 5장 참조.
- **자동 발행** — 영상도 안 한다. 웬비디아도 안 한다. 우리도 안 한다. 판단 일치.

## 7. 다음 액션 (우선순위)

### 1순위 — 임시저장 마지막 1cm (연결 층의 유일한 진짜 구멍)

방향은 이미 잡혀 있다: `naver-draft-bg.js`가 맞다. **퍼펫티어를 쓰지 않는다**는 게 핵심이다.
- 퍼펫티어와 확장은 `chrome.debugger` 자리를 놓고 싸운다. **둘 중 하나만 쓴다.**
- 확장에는 이미 `saveDraft()`와 무인 모드 결과 보고선(`background.js`)이 있다. 남은 건 **사람이 버튼을 안 눌러도 되게 하는 신호 하나**다.
- 크롬은 **최소화로** 띄운다. 포커스를 뺏으면 사장님이 다른 창에 타자 치던 중에 원고가 붙는다(실제 사고 있었음).

### 2순위 — 무인 러너 + 스케줄러 1개

n8n 대신 이걸 만든다. n8n의 ④(실행이력·재시도·실패알림)를 스크립트로 산다.

```
scripts/run-daily.js
  · 편집국에서 오늘 발행 예정 원고 꺼냄 (schedule.js가 배정한 publishAt 기준)
  · naver-draft-bg.js 호출
  · 실패하면 2회 재시도 → 그래도 실패면 로그 + 알림
  · 실행 이력 남김 (언제 · 무슨 글 · 성공/실패 · 이유)
```
작업 스케줄러에 하나만 등록한다 (`GwBackupEvery2h`와 같은 방식으로 검증됨).

### 3순위 — 성과 루프 닫기 ★ 비용 0, 오늘 가능

네이버 블로그 통계를 `gw_analytics_2026`에 넣는 입구를 만든다.
지금은 발행만 기록되고 **결과가 안 돌아온다.** 배율표가 비어 있으면 그릇만 있는 것이다.
주 1회 통계 붙여넣기 → 저조 원인 · 다음 글 방향 · 프롬프트 수정안.

### 4순위 — `topics.md` 인박스

편집국에 한 줄 입력칸. 비어 있으면 RSS 자동 소재로, 채워져 있으면 그걸 우선.

영상은 **연결**을 우리보다 잘한다. 우리는 **품질**을 영상보다 훨씬 잘한다.
n8n을 들이는 게 아니라, 우리 품질 위에 **임시저장 + 스케줄러 + 성과 회신** 세 개만 얹으면 된다.
