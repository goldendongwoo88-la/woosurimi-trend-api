# public/k/ — 지식교양 글 (웹판)

## 왜 이 폴더가 있는가

네이버 블로그는 AI 크롤러를 전부 막아뒀습니다. `blog.naver.com/robots.txt` 에서 직접 확인한 내용입니다.

```
# BOT ACCESS FOR THE PURPOSES OF AI TRAINING AND
# RETRIEVAL-AUGMENTED GENERATION (RAG) IS STRICTLY PROHIBITED.
User-agent: GPTBot            Disallow: /
User-agent: OAI-SearchBot     Disallow: /      ← ChatGPT 검색
User-agent: PerplexityBot     Disallow: /      ← Perplexity
User-agent: Claude-SearchBot  Disallow: /      ← Claude 검색
User-agent: ClaudeBot         Disallow: /
User-agent: Google-Extended   Disallow: /
User-agent: meta-externalagent / Applebot-Extended / CCBot  Disallow: /
```

학습용 봇뿐 아니라 **검색용 봇까지 막혀 있습니다.** 즉 네이버 블로그에 올린 글은
ChatGPT·Claude·Perplexity 답변에 출처로 뜨지 않습니다. 원고를 어떻게 고쳐도 안 됩니다.

그래서 AI 검색 노출을 원하면 **우리가 robots.txt 를 직접 제어하는 이 사이트**에
올리는 수밖에 없습니다. 이 폴더가 그 자리입니다.

## 네이버판과 웹판의 차이

같은 소재를 두 판으로 냅니다. **문장은 절대 복사하지 않습니다.**

| | 네이버판 | 웹판 (이 폴더) |
|---|---|---|
| 목적 | 홈판·검색 유입 | AI 인용 + 구글 검색 |
| 분량 | 1,000~1,500자 | 상한 없음 |
| 제목 | 후킹 장치 2개 이상 | 질문 원문 그대로 |
| 소제목 | 10자 내외 | 질문 원문 그대로 |
| 구조 | 인용구 구획만 (표·목차 금지) | h2, table 자유 |
| 출처 링크 | 3편 중 1편 이하 | 전부 노출 |
| 구조화 데이터 | 불가 | Article + FAQPage JSON-LD |

### 왜 문장을 복사하면 안 되는가

네이버 D.I.A 원본성 판정에서 불리해질 수 있습니다. `knowledge-culture` 스킬도
이미지에 대해 같은 경고를 하고 있습니다 — "여러 매체가 동일하게 쓰는 자료 이미지는
다른 글과 겹쳐 원본성 판별에 불리할 수 있어". 이미지가 그렇다면 본문은 더합니다.

네이버가 외부 사이트 텍스트와 대조하는지는 공개된 바 없습니다. **확인된 사실이 아니라
위험 회피 판단입니다.** 다만 회피 비용(문장을 새로 씀)이 낮아서 회피하는 쪽이 낫습니다.

**사실·수치·출처만 공유하고 문장은 각각 새로 씁니다.**

### 발행 순서

**네이버 먼저, 웹판은 3~7일 뒤.** 수익의 주 경로가 네이버 검색이므로 색인 선점을
네이버에 줍니다.

## 글 추가하는 법

1. `_TEMPLATE.html` 을 복사해서 `<슬러그>.html` 로 저장합니다
   - 슬러그는 영문 소문자·숫자·하이픈만. 예: `eocheoguni.html`
2. `{{ }}` 로 표시된 곳을 전부 채웁니다. `<head>` 안이 제일 중요합니다
3. 같은 이름의 `<슬러그>.md` 를 만들어 같은 내용을 마크다운으로 둡니다
4. `index.html` 의 주석 처리된 `<a class="card-link">` 예시를 복사해서 목록에 추가합니다
5. `../sitemap.xml` 에 `<url>` 항목을 추가합니다

서버 코드는 건드리지 않습니다. `src/index.js` 의 `express.static` 이 `public/` 을
통째로 서빙하므로 파일만 놓으면 `/k/<슬러그>.html` 로 바로 열립니다.

## 본문 작성 규칙 (AI 인용용)

`knowledge-culture` 스킬의 홈판 규칙과 **다릅니다.** 웹판에만 적용합니다.

1. **정의문으로 시작** — 첫 문장은 `[키워드]는 ○○이다` 형태. 부정문으로 시작하지 않습니다.
   정설이 없어도 사전적 뜻을 먼저 주고 미확정을 뒤에 붙입니다.
2. **단락 자립** — 각 `h2` 아래 첫 문단의 주어에 지시어(이·그·해당)를 쓰지 않습니다.
   그 문단만 떼어 읽어도 뜻이 통해야 합니다. AI 인용은 단락 단위로 잘려 들어갑니다.
3. **덩어리로 쓰기** — 2~3문장을 한 문단에 이어 씁니다. 문장마다 개행하지 않습니다.
   네이버판의 "한 문단 한 문장, 15자" 규칙은 여기 적용하지 않습니다.
4. **출처는 완결 문장** — `[기관명]의 [문서·조사명]([연도] 기준)에 따르면 [주장]이다.`
   그 한 문장만 읽어도 누가 언제 무엇을 말했는지 알 수 있어야 합니다.
5. **소제목 = 질문 원문** — 10자 제한 없습니다. 바로 다음 문장이 그 질문의 답입니다.

## 알아둘 것

- **`llms.txt` 는 표준이 아닙니다.** 2024년 9월 커뮤니티 제안이고, OpenAI·Anthropic·
  Perplexity 중 어느 곳도 이걸 읽는다고 공식 선언한 적 없습니다. 비용이 낮아 넣어뒀지만
  효과는 약속할 수 없습니다.
- **JSON-LD 가 AI 인용을 올린다는 것도 검증되지 않았습니다.** 구글 리치 결과용으로
  문서화된 걸 AEO 로 확대 해석한 면이 있습니다. 다만 구글 검색에는 실제로 쓰이므로
  넣어서 손해는 없습니다.
- **자체 도메인이 사실상 전제입니다.** `onrender.com` 서브도메인으로는 같은 내용에서
  네이버한테 정본 자리를 뺏기기 쉽습니다.
- 소재가 불리합니다. 어원·뜻·상식은 나무위키와 국립국어원이 이미 점유한 영역입니다.
  **비집고 들어갈 틈은 "나무위키에 없는 롱테일"과 "본인만 가진 1차 데이터" 둘뿐입니다.**
  `knowledge-culture` 스킬의 "지역·상황별 차이" 규칙이 이미 그 방향을 겨냥하고 있습니다.
