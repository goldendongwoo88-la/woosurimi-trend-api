# 우수리미 트렌드 API

Google 트렌드 대한민국(`geo=KR`) 실시간 인기 검색어를 주기적으로 가져와 캐시하고, 여러분의 사이트가 호출할 수 있는 REST API로 제공하는 작은 백엔드입니다.

## 왜 이게 따로 필요한가

브라우저에서 바로 `trends.google.com`을 호출하면 CORS·차단 문제로 대부분 실패합니다. 그래서 서버가 대신 주기적으로 가져와서 저장해두고, 여러분의 프론트엔드는 이 서버의 API만 호출하는 구조가 필요합니다. 이 프로젝트가 그 서버입니다.

**중요 — claude.ai에 게시한 "우수리미 AI" Artifact 페이지에는 이 API를 직접 연결할 수 없습니다.** Artifact는 보안상 외부 서버로 요청을 보내지 못하도록 막혀 있습니다. 그래서 이 프로젝트 자체가 API와 웹페이지(`public/` 폴더, 아래 "웹사이트 화면" 섹션 참고)를 함께 서빙하는 진짜 웹사이트 역할을 합니다 — 이 프로젝트를 배포하면(맨 아래 "Render에 배포하기" 섹션 참고) 그 자체로 완결된 사이트가 됩니다.

## 로컬에서 실행하기

```bash
npm install
npm start
```

`http://localhost:3000/api/trends` 를 호출하면 아래와 비슷한 JSON이 나옵니다.

```json
{
  "source": "google-trends-kr",
  "fetchedAt": "2026-08-24T04:20:00.000Z",
  "items": [
    { "rank": 1, "term": "염경엽", "approxTraffic": "20000+", "link": "...", "publishedAt": "..." }
  ]
}
```

서버를 처음 켠 시점에는 아직 데이터가 없어서 `/api/trends`가 잠깐 503을 반환할 수 있습니다 (`/api/health`로 마지막 수집 상태를 확인할 수 있습니다). 몇 초~몇 분 안에 첫 수집이 끝나면 정상적으로 데이터가 나옵니다.

**개발 환경에 따라 이 요청 자체가 막힐 수 있습니다.** 이 코드를 만든 샌드박스 환경에서는 `trends.google.com`으로 나가는 요청이 네트워크 정책상 403으로 막혀서, 코드 구조(서버 기동, API 응답, 에러 처리)까지는 확인했지만 실제 수집 성공까지는 이 환경에서 검증하지 못했습니다. Render·Railway·Vercel 같은 일반적인 호스팅 환경에서는 이런 제약이 없어서 정상적으로 동작할 가능성이 높지만, Google 트렌드 쪽에서 특정 IP를 차단할 가능성은 항상 존재합니다 — 배포 후 `/api/health`로 꼭 확인해 보세요.

## Render에 배포하기 (진짜 인터넷 주소로 24시간 열어두기)

지금까지는 사용자님 컴퓨터에서 `npm start`로 켜야만 작동했는데, 컴퓨터를 끄면 사이트도 같이 꺼집니다. 아래 순서대로 하시면 `https://무언가.onrender.com` 같은 진짜 인터넷 주소가 생기고, 컴퓨터를 꺼도 계속 열려 있습니다(무료 플랜의 특성은 맨 아래 "무료 플랜에서 꼭 알아둘 점" 참고).

### 1단계 — GitHub 계정 만들고 코드 올리기

Render는 GitHub에 올려둔 코드를 가져다가 자동으로 배포하는 방식이라, 먼저 이 프로젝트를 GitHub에 올려야 합니다.

1. [github.com](https://github.com) 에서 계정이 없으면 회원가입합니다.
2. 로그인한 뒤 오른쪽 위 **"+"** 버튼 → **"New repository"** 를 누릅니다.
3. Repository name에 `woosurimi-trend-api` 입력, Public/Private 아무거나 선택(Private이어도 배포엔 문제없어요), 나머지는 기본값 그대로 두고 **"Create repository"** 를 누릅니다.
4. 저장소가 만들어지면 화면에 나오는 주소를 복사해 둡니다. `https://github.com/내아이디/woosurimi-trend-api.git` 같은 형태입니다.
5. [git-scm.com](https://git-scm.com/downloads) 에서 Git이 설치되어 있지 않다면 설치합니다(Node처럼 "다음, 다음" 눌러서 설치하면 됩니다).
6. cmd(명령 프롬프트)를 프로젝트 폴더(`woosurimi-trend-api\woosurimi-trend-api`)에서 열고, 아래를 한 줄씩 입력합니다(3번의 `github.com/...` 주소는 본인 것으로 바꿔주세요).

```
git init
git add .
git commit -m "우수리미 트렌드 API 첫 업로드"
git branch -M main
git remote add origin https://github.com/내아이디/woosurimi-trend-api.git
git push -u origin main
```

`git push` 단계에서 GitHub 로그인 창이 뜨면 로그인해 주세요. `.env` 파일은 `.gitignore`에 이미 등록되어 있어서 실수로 올라가지 않습니다(API 키가 깃허브에 공개되는 걸 막아줘요) — 대신 API 키는 3단계에서 Render에 따로 등록합니다.

이후 코드를 수정할 때마다 같은 폴더에서 `git add .` → `git commit -m "수정 내용"` → `git push`만 다시 해주면 됩니다.

### 2단계 — Render 가입하고 서비스 만들기

1. [render.com](https://render.com) 에서 "Get Started" → GitHub 계정으로 가입/로그인합니다(GitHub 계정 연동을 허용해 주세요).
2. 대시보드에서 **"New +"** → **"Web Service"** 를 누릅니다.
3. 방금 올린 `woosurimi-trend-api` 저장소를 찾아서 **"Connect"** 를 누릅니다.
4. 설정 화면에서:
   - **Name**: 원하는 이름 (예: `woosurimi-trend-api`) — 이게 나중에 주소의 일부가 됩니다.
   - **Region**: `Singapore` (한국에서 가장 가까운 지역이라 속도가 더 빠릅니다)
   - **Branch**: `main`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`
5. **"Environment Variables"** 항목에서, `.env` 파일에 있던 값들을 하나씩 Key/Value로 등록해 주세요.

```
NAVER_APIHUB_KEY_ID       = (사용자님의 값)
NAVER_APIHUB_KEY_SECRET   = (사용자님의 값)
NAVER_AD_API_KEY          = (사용자님의 값)
NAVER_AD_SECRET_KEY       = (사용자님의 값)
NAVER_AD_CUSTOMER_ID      = (사용자님의 값)
```

(`PORT`는 등록하지 마세요 — Render가 자동으로 넣어줍니다. `REFRESH_CRON`, `OPPORTUNITY_TTL_MS`는 선택사항이라 안 넣으면 기본값이 쓰입니다.)

6. **"Create Web Service"** 를 누르면 첫 배포가 시작됩니다. 로그 화면에 설치·빌드 과정이 쭉 나오고, 몇 분 뒤 `우수리미 트렌드 API 서버 실행 중...` 메시지가 보이면 성공입니다.
7. 화면 위쪽에 `https://woosurimi-trend-api-xxxx.onrender.com` 같은 진짜 주소가 생겨요. 그 주소로 들어가시면 로컬에서 보던 것과 똑같은 홈 화면이 나옵니다.

### 무료 플랜에서 꼭 알아둘 점

- **잠깐 쉬었다 깨어남**: 무료 플랜은 15분 동안 아무도 접속하지 않으면 서버가 잠들어요. 그 뒤 첫 접속은 서버가 다시 깨어나느라 30초~1분 정도 로딩이 걸릴 수 있습니다(그다음부터는 빨라져요). 24시간 완전히 끊김 없이 켜두고 싶으면 Render의 유료 플랜(월 7달러부터)이 필요합니다.
- **숏폼으로 만든 mp4 파일은 영구 저장이 안 됩니다**: 무료 플랜은 서버가 재시작되거나(잠들었다 깨어나는 것 포함) 새로 배포할 때 디스크에 저장해둔 파일이 사라질 수 있어요. `/shortform.html`에서 영상을 만들면 그 순간에는 재생·다운로드가 되지만, **만들자마자 바로 다운로드해 두시는 걸 추천**합니다. 영상을 서버에 계속 보관하려면 Render의 유료 "Persistent Disk" 옵션을 추가하거나, AWS S3/Cloudflare R2 같은 별도 저장소를 연결해야 하는데, 이건 별도 작업이 필요해서 요청 주시면 이어서 도와드릴게요.
- **코드 수정 후 재배포**: 로컬에서 코드를 고친 뒤 1단계의 `git add .` → `git commit` → `git push`만 다시 하면, Render가 자동으로 새 코드를 감지해서 재배포해 줍니다.

Railway·Fly.io·직접 운영하는 VPS 등 Node.js를 상시 실행할 수 있는 곳이면 같은 방식(GitHub 연결 → 환경변수 등록 → 빌드/시작 명령어)으로 배포할 수 있습니다. (Vercel처럼 서버리스 함수만 지원하는 곳은 `node-cron`이 계속 살아있지 못하고, ffmpeg 렌더링처럼 시간이 걸리는 작업에도 잘 안 맞아서 이 프로젝트엔 권장하지 않습니다.)

## 프론트엔드에서 호출하는 예시

```html
<script>
  async function loadTrends() {
    const res = await fetch("https://your-app.onrender.com/api/trends");
    const data = await res.json();
    console.log(data.fetchedAt, data.items);
    // data.items를 우수리미 AI 페이지의 "오늘의 인기 검색어" 리스트에 그대로 렌더링하면 됩니다.
  }
  loadTrends();
  setInterval(loadTrends, 5 * 60 * 1000); // 5분마다 갱신
</script>
```

## 갱신 주기 조정

기본은 10분(`*/10 * * * *`)입니다. 환경 변수 `REFRESH_CRON`으로 바꿀 수 있습니다.

```bash
REFRESH_CRON="*/5 * * * *" npm start   # 5분마다
```

너무 짧게 잡으면(예: 초 단위) 소스 서버에 부담을 주고 차단될 위험이 커지므로 권장하지 않습니다.

## 블로그 글감 찾기 — "기회 키워드" API (네이버 공식 API 사용)

`/api/trends`(구글 트렌드)와는 별개로, **진짜 네이버 데이터**를 쓰는 기능이 하나 더 있습니다. 네이버가 공식적으로 무료 제공하는 API 두 개를 조합해서, "검색은 많이 되는데 아직 그 키워드로 쓴 블로그 글은 적은" 키워드를 찾아줍니다 — 흔히 말하는 "황금 키워드"입니다.

### 왜 이 방식인가

네이버는 "지금 뜨는 검색어 순위"를 더 이상 공식적으로 주지 않습니다(2021년에 폐지). 대신 아래 두 API는 막히지 않고, 신청만 하면 바로 씁니다.

- **검색광고 키워드도구** — 씨앗 키워드 → 연관 키워드 + 월간 PC/모바일 검색량
- **오픈 API 블로그 검색** — 특정 키워드로 이미 올라온 블로그 글이 몇 개인지(경쟁 정도)

이 둘을 `(월간 검색량) ÷ (이미 올라온 글 수 + 1)` 로 계산해서 점수가 높은 순으로 정렬한 게 "기회 키워드"입니다.

### API 키 발급받는 법

> **2026년 업데이트:** 예전에는 developers.naver.com "애플리케이션 등록" 화면의 "사용 API" 목록에 "검색"이라는 항목이 있어서 그것만 체크하면 블로그 검색 API를 바로 쓸 수 있었습니다. **지금은 그 항목이 사라졌습니다** — 네이버가 검색 관련 API들을 developers.naver.com에서 떼어내 **"NAVER API HUB"**라는 새 플랫폼(네이버 클라우드 플랫폼 소속)으로 옮겼기 때문입니다. "사용 API" 드롭다운을 아무리 스크롤해도 "검색"이 안 보이는 게 정상이고, 아래는 새 플랫폼 기준 절차입니다.

**1) 블로그 검색 API — NAVER API HUB (네이버 클라우드 플랫폼)**
1. [apihub.ncloud.com](https://apihub.ncloud.com) 접속 → 네이버 계정으로 로그인 (네이버 클라우드 플랫폼 계정이 없으면 이 과정에서 새로 만들게 됩니다 — 개인/비사업자로도 가입할 수 있습니다. 다만 가입 중 휴대폰 본인인증이나 결제수단(카드) 등록을 요구할 수 있는데, 이 부분은 저희도 화면이 계속 바뀌어서 100% 장담은 못 드립니다 — 화면에 나오는 안내를 그대로 따라가시면 됩니다)
2. NAVER API HUB 콘솔에서 "검색 API" 카테고리를 찾아 "블로그 검색"을 이용 신청합니다 (무료 이용량 안에서는 비용이 들지 않습니다)
3. 신청이 승인되면 콘솔의 "인증키 관리" 화면에서 **Client ID / Client Secret**(또는 "인증키 ID/Secret")이 발급됩니다 — 이게 `NAVER_APIHUB_KEY_ID` / `NAVER_APIHUB_KEY_SECRET`
4. 화면 구성이나 메뉴 이름이 안내와 조금 달라도 당황하지 마세요 — "이용 신청" → "인증키 발급" 흐름은 동일합니다. 막히면 [NAVER API HUB 사용 가이드](https://guide.ncloud-docs.com/docs/apihub-use)를 참고하세요.

**2) 검색광고 API (키워드도구용) — searchad.naver.com**
1. [네이버 검색광고](https://searchad.naver.com)에 회원가입 (네이버 계정 연동 가능, 광고를 실제로 집행하지 않아도 가입만으로 API 사용 가능)
2. 로그인 후 우측 상단 내 계정 → "도구" → "API 사용 관리"
3. "API 사용 신청" → 승인되면 **API 키(Access License) / Secret Key**가 발급되고, 화면에 내 **CUSTOMER ID**(숫자)도 표시됩니다
4. 이 세 값이 `NAVER_AD_API_KEY` / `NAVER_AD_SECRET_KEY` / `NAVER_AD_CUSTOMER_ID`

발급받은 값을 `.env` 파일에 채워 넣으세요 (`.env.example`을 복사해서 `.env`로 저장 후 값 입력).

```bash
cp .env.example .env
# .env 파일을 열어서 5개 값을 채워 넣습니다
npm start
```

### 사용법

```
GET /api/categories
→ {"categories":["국내여행","패션/미용","반려동물","육아/결혼","맛집","스포츠","사회/정치","IT/컴퓨터","자동차","비즈니스/경제","건강/의학","요리/레시피","세계여행","원예/재배","상품리뷰","인테리어/DIY"]}

GET /api/opportunity?category=패션/미용
→ {
    "category": "패션/미용",
    "generatedAt": "2026-08-24T04:30:00.000Z",
    "cached": false,
    "items": [
      { "keyword": "가을 니트 세탁법", "monthlySearchVolume": 8200, "blogPostCount": 340, "docPerSearch": 0.04, "competition": "낮음", "opportunityScore": 24.06 },
      ...
    ]
  }
```

`opportunityScore`가 높을수록, `docPerSearch`(문서/검색 = 블로그 문서 수 ÷ 월간 검색량)는 **낮을수록** "찾는 사람은 많은데 글은 적은" 좋은 틈새 키워드입니다 — 서로 반대 방향으로 움직이는 값이라는 점을 참고해 주세요. `/opportunity.html`에서는 순위 번호 + 점수 배지 + 검색량/문서수/문서-검색 비율 카드 형태로 보여주고, 화면 상단에 "낮을수록 좋다"는 안내 문구를 항상 표시합니다. 카테고리별 씨앗 키워드는 `src/opportunityFinder.js`의 `CATEGORY_SEEDS`에서 자유롭게 추가·수정할 수 있습니다 — 사장님 블로그 주제에 맞게 씨앗 키워드를 바꾸면 결과도 그에 맞게 바뀝니다.

결과는 카테고리당 기본 10분 캐시됩니다(`OPPORTUNITY_TTL_MS`로 조정 가능) — 네이버 API 호출 횟수를 아끼기 위해서입니다.

### "오늘 발행된 글" 기준으로 보기 — `mode=today`

```
GET /api/opportunity?category=자동차&mode=today
```

`mode=today`를 붙이면 전체 기간이 아니라 **오늘(한국시간) 올라온 블로그 글 수**를 기준으로 기회 점수를 계산합니다. "요즘 막 검색은 느는데 아직 아무도 안 쓴" 키워드를 찾을 때 유용합니다.

⚠️ 다만 한 가지 한계가 있어요 — 네이버 블로그 검색 API는 글이 올라온 **날짜**만 주고 **시:분:초**는 주지 않습니다. 그래서 정확히 "지금부터 24시간 전"을 계산할 수 없고, 대신 "오늘 날짜로 찍힌 글"을 세는 방식으로 근사합니다(확인하는 시각에 따라 몇 분 전~어제 자정 직전 글까지 섞일 수 있어요). 또 한 번에 최대 100개까지만 확인하기 때문에, 오늘 글이 100개를 넘는 인기 키워드는 `blogPostCountLabel`에 `"100+"`로 표시됩니다.

## 엔터(연예) 최신 뉴스 — `/api/entertainment/news`

블로그와 별개로, 네이버 뉴스 검색 API를 이용한 기능도 추가했습니다. 뉴스 API는 블로그와 달리 `pubDate`에 **정확한 시:분:초**가 들어있어서, 진짜로 "최근 24시간 이내"를 정확하게 걸러낼 수 있습니다.

⚠️ 이 기능을 쓰려면 NAVER API HUB 콘솔에서 **"뉴스"(NAVER Search News API)**를 추가로 이용 신청해야 합니다. "블로그"만 신청하셨다면 아래 요청이 에러를 낼 수 있어요 — 콘솔의 기존 애플리케이션(예: woosoorimi)에 "뉴스"를 추가하거나, 안 되면 새 애플리케이션으로 "뉴스"를 신청한 뒤 그 Client ID/Secret으로 `.env`를 업데이트해주세요.

### 썸네일 이미지

네이버 뉴스 검색 API 응답에는 썸네일/이미지 필드가 원래 없습니다(공식 문서 기준 title/originallink/link/description/pubDate뿐입니다). 대신 각 기사의 원문 페이지(`originallink`)에 실제로 접속해서 그 페이지에 걸려있는 대표 이미지(`og:image` 메타태그)를 읽어와 채워줍니다 — 가짜 이미지가 아니라 그 기사 원문에 실제로 쓰인 썸네일입니다. 다만 이 과정 때문에 응답이 조금 느려질 수 있고, 언론사 사이트에 따라 이미지가 안 잡힐 수도 있습니다(그런 경우 `image: null`로 오고, 데모 화면에서는 회색 박스로 대신 표시됩니다).

### 탭 구성

```
GET /api/entertainment/categories
→ {"categories":["전체","최신뉴스","드라마","영화","뮤직","연애","랭킹"]}
```

- **전체 / 최신뉴스** — 드라마·영화·뮤직·연애 4개 소분류를 실제로 각각 검색한 뒤, 중복 링크를 제거하고 최신순으로 합친 목록입니다. 둘 다 같은 로직(4개 합치기)을 쓰지만 **시간 범위 기본값이 다릅니다** — "전체"는 최근 24시간, "최신뉴스"는 더 좁게 최근 6시간만 보여줍니다("방금 뜬 것"이라는 의미에 맞게). `?hours=숫자`를 직접 붙이면 이 기본값 대신 원하는 시간으로 바꿀 수 있습니다 (예: `?category=최신뉴스&hours=3`).
- **드라마 / 영화 / 뮤직 / 연애** — 각 소분류만 따로 검색합니다.
- **랭킹** — 아래 별도 섹션 참고.

```
GET /api/entertainment/news?category=드라마&hours=24
→ {
    "category": "드라마",
    "query": "드라마",
    "hours": 24,
    "generatedAt": "2026-08-24T06:30:00.000Z",
    "count": 12,
    "items": [
      { "title": "...", "link": "...", "description": "...", "pubDate": "2026-08-24T05:10:00.000Z", "press": "..." },
      ...
    ]
  }
```

### 랭킹 탭 — `/api/entertainment/ranking` (⚠️ 진짜 조회수 랭킹이 아닙니다)

네이버 "엔터" 홈의 **"오늘의 엔터 랭킹"(AiRS 추천)**, 그리고 "랭킹" 탭의 **"많이 본 뉴스" / "5분 많이 본" / "공감 많은"**은 모두 네이버가 자체적으로 집계하는 조회수·공감수 데이터를 바탕으로 합니다. 이 데이터는 네이버 내부 시스템에서만 계산되고, **뉴스 검색 API 응답에는 조회수·공감수 필드가 아예 존재하지 않습니다.** 그래서 이 세 가지는 어떤 방법으로도(근사치조차) 재현이 불가능합니다 — 없는 데이터를 있는 것처럼 흉내 내지 않기 위해, 이 이름 그대로는 만들지 않았습니다.

대신 실제로 얻을 수 있는 데이터로 만든 **"화제성 랭킹"**을 제공합니다: 최근 뉴스들을 제목 기준으로 "같은 이슈를 다룬 기사"끼리 묶고(예: 여러 언론사가 동시에 다룬 이슈), 그 기사 수·언론사 수가 많은 순으로 정렬합니다. "몇 명이 봤는지"가 아니라 "몇 개 언론사가 동시에 다뤘는지"를 화제성의 대리 지표로 쓰는 방식입니다. 제목 텍스트만으로 대충 묶기 때문에 완벽하지 않고(서로 다른 기사가 묶이거나, 표현이 달라 같은 이슈인데 못 묶이는 경우가 있을 수 있음) 참고용으로만 봐주세요.

```
GET /api/entertainment/ranking?hours=24
→ {
    "category": "랭킹",
    "note": "네이버의 실제 조회수·공감수는 외부에 공개되지 않아서 ... '화제성' 랭킹입니다.",
    "hours": 24,
    "generatedAt": "2026-08-24T06:30:00.000Z",
    "count": 8,
    "items": [
      {
        "title": "...", "link": "...", "pubDate": "...", "press": "...",
        "articleCount": 5, "pressCount": 4,
        "relatedArticles": [ { "title": "...", "link": "...", "press": "..." }, ... ]
      },
      ...
    ]
  }
```

### 숏폼 자동 제작 — 두 가지 모드 (캡컷 "자동컷"과 비슷한 구조)

- **링크컷** — 블로그 글 링크, 네이버 쇼핑(스마트스토어) 링크, 여행 커넥트 링크를 넣으면 그 페이지에 있는 **실제 사진과 본문 문장**을 그대로 가져와서 장면을 짭니다.
- **자동컷** — 링크 없이, **사용자가 직접 고른 사진들**과 한 줄 주제로 장면을 짭니다.

두 모드 모두 결과는 같은 형태의 `scenes` 배열이라, 아래 템플릿/배경음악/AI 성우/렌더링 과정은 완전히 동일하게 이어집니다.

#### 링크컷 — `/api/shortform/plan`

```
POST /api/shortform/plan
Body: { "url": "https://blog.naver.com/...", "source": "blog" }   ("source": "blog" | "shopping" | "travel")
→ {
    "sourceUrl": "...", "source": "blog", "sourceTitle": "...",
    "imagesFound": 5,
    "scenes": [
      { "index": 1, "role": "hook", "caption": "...", "image": "https://..." },
      { "index": 2, "role": "body", "caption": "...", "image": "https://..." },
      ...
      { "index": 6, "role": "cta", "caption": "...", "image": "https://..." }
    ],
    "fullScript": "...",
    "hashtags": ["#...", ...],
    "note": "..."
  }
```

#### 자동컷 — `/api/shortform/plan-from-photos`

```
POST /api/shortform/plan-from-photos   (multipart/form-data)
  photos: 사진 파일 여러 장 (최대 12장, 각 15MB 이하) — 순서대로 장면이 됩니다
  topic: 영상 주제를 한 줄로 (필수)
  source: (선택) "blog" | "shopping" | "travel" — 후킹/CTA 문구 톤만 다르게
  summaryText: (선택) 본문 요약 문단 — 넣으면 문장 단위로 잘라 사진 순서에 맞춰 자막으로 씀
  captions: (선택) JSON 배열 문자열 — photos와 같은 순서로 사진별 자막을 직접 지정
→ (링크컷과 동일한 형태의 scenes/fullScript/hashtags/note)
```

사진별 자막을 직접 안 넣으면, AI가 사진 내용을 임의로 "본 것처럼" 지어내지 않고 주제 문구를 짧게 변형한 일반적인 문구로 채웁니다 — `summaryText`를 넣으면 그 실제 문장으로 채워집니다.

### 숏폼 자동 제작 2단계 — `/api/shortform/render` (진짜 mp4 영상 파일)

1단계에서 만든 `scenes`를 그대로 넘기면, 서버가 ffmpeg로 **실제 mp4 영상 파일**을 만들어줍니다. 사진마다 세로 화면(720×1280, 9:16)에 맞게 **포토카드(하얀 테두리 카드 + 같은 사진을 흐리게 확대한 배경) 또는 화면 꽉 채우기** 스타일로 배치하고 **켄번즈(Ken Burns) 확대·축소·팬 애니메이션**을 넣은 뒤, 자막을 굵은 글씨 + 반투명 박스로 입힙니다. 장면과 장면 사이는 그냥 잘라 붙이는(하드컷) 게 아니라 **xfade/acrossfade로 부드럽게 겹쳐 넘어가는 크로스페이드 전환**을 넣고, 영상 맨 처음과 맨 끝에만 검은 화면 페이드 인/아웃을 넣어서 순서대로 이어 붙입니다. **배경음악**은 직접 mp3를 올리거나, 아래 "배경음악 자동 추천" 라이브러리 중 하나를 골라서 넣을 수 있고, **AI 성우 나레이션**을 요청하면(해당 서비스 API 키가 서버에 설정된 경우) 장면별로 실제 목소리도 입혀줍니다. 완성된 영상 주소는 **QR 코드**로도 함께 내려줘서 휴대폰으로 바로 접속해 받을 수 있습니다.

**자막 표시 방식**: 대사가 길어도 화면에 한꺼번에 다 띄우지 않고, **2줄씩 순서대로 바뀌면서** 보여줍니다(글자는 하나도 빠지지 않고 전부 나옵니다). 대사가 길면 2줄 구간이 여러 번 이어지는데, 그만큼 장면 길이도 자동으로 늘어나서 너무 빨리 지나가지 않게 합니다.

**사진 품질**: 원문 페이지의 이미지 중 실제 사진이 아닌 **스티커/이모티콘 같은 장식 그래픽은 자동으로 걸러내고**, 사용하는 사진은(네이버 블로그 이미지의 경우) 화면에 크게 나와도 잘 뭉개지지 않도록 더 높은 해상도 버전을 받아오도록 되어 있습니다. 다만 원문 자체에 올라간 사진 해상도가 원래 낮으면(예: 아주 작은 썸네일) 그 이상으로 선명하게 만들 수는 없습니다 — 이 경우 켄번즈 확대율이 커서 더 흐려 보일 수 있으니, 그럴 땐 `animate=false`로 정지 사진으로 만드는 것도 방법입니다.

```
POST /api/shortform/render   (multipart/form-data)
  scenes: (JSON 문자열) — 1단계 응답의 scenes 배열 그대로
  durationPerScene: (선택) 장면당 초 — 기본 3, 최대 12장면 (나레이션이 더 길면 자동으로 늘어남)
  bgm: (선택) 직접 업로드하는 mp3 등 오디오 파일, 최대 15MB — 있으면 이게 우선
  bgmId: (선택) 아래 추천 라이브러리 트랙 id (예: "calm-piano") — bgm 파일이 없을 때 사용
  animate: (선택) "false"면 켄번즈 애니메이션 없이 정지 사진 (기본 true)
  frameStyle: (선택) "polaroid"(기본, 하얀 테두리 포토카드+흐린 확대 배경) | "full"(화면 꽉 채우기)
  voiceProvider: (선택) "clova" | "typecast" | "elevenlabs"
  voiceId: (선택) 서비스별 목소리 식별자 (비워두면 서비스 기본 목소리)
  templateId: (선택) 아래 "자막 디자인 템플릿" 중 하나의 id (기본 "bold-black")
→ {
    "fileName": "xxxx.mp4",
    "publicPath": "/renders/xxxx.mp4",
    "videoUrl": "https://내주소.onrender.com/renders/xxxx.mp4",
    "qrDataUrl": "data:image/png;base64,...",   ← 이 주소를 QR 이미지로 바로 그려둔 것
    "durationSec": 18,
    "narration": { "used": true, "provider": "elevenlabs", "scenesWithVoice": 6 },
    "narrationNote": "...",
    "note": "..."
  }
```

`publicPath`로 바로 접속하면 영상이 재생/다운로드됩니다. `/shortform.html` 화면에서는 기획안을 만든 뒤 배경음악을 고르고, 원하면 성우 서비스를 선택한 다음 "영상 생성하기"를 누르면 결과 영상과 다운로드 QR 코드가 바로 나옵니다.

#### 자막 디자인 템플릿 5종 (`/api/shortform/template-suggestions`)

캡컷의 "템플릿 고르기"처럼, 자막 색상/박스/위치가 서로 다른 5가지 디자인(`src/videoTemplates.js`) 중 대본에 어울리는 순서로 추천해줍니다.

```
POST /api/shortform/template-suggestions
Body: { "scenes": [...] }
→ { "note": "...", "templates": [ { "id": "bold-black", "label": "볼드 블랙", "description": "...", "score": 2 }, ... 5개 ] }
```

5종: 볼드 블랙(무난) / 감성 크림(카페·여행·브이로그) / 네온 핑크(숏폼·트렌드) / 비비드 옐로우 상단(이벤트·세일) / 클린 블루(제품·정보성).

#### 🤖 AI 추천 5개 영상 — `/api/shortform/recommend`

캡컷 자동컷처럼, 대본(scenes) 하나로 **"자막 템플릿 + 배경음악 + 성우 목소리" 조합 5가지**를 AI가 알아서 짜고, 각각 짧은 미리보기 영상(앞부분 최대 3장면, 나레이션 없이, 속도 우선)까지 만들어서 보여줍니다. 마음에 드는 조합을 고르면 그 `templateId`/`bgmId`/`voiceProvider`를 그대로 `/api/shortform/render`에 넘겨서 완성도 높은 최종 영상을 만들 수 있습니다.

```
POST /api/shortform/recommend
Body: { "scenes": [...] }
→ {
    "note": "...",
    "voiceProvidersReady": [ { "provider": "typecast", "label": "..." }, ... ],  ← 실제 키가 설정된 서비스만
    "recipes": [
      {
        "recipeId": "recipe-1",
        "templateId": "soft-cream", "templateLabel": "감성 크림",
        "bgmId": "calm-piano", "bgmLabel": "잔잔한 피아노풍",
        "voiceProvider": "typecast" (또는 null), "voiceLabel": "...",
        "previewUrl": "https://.../renders/xxxx.mp4",
        "previewError": null
      },
      ... 5개
    ]
  }
```

서버 부하를 줄이기 위해 5개를 동시에가 아니라 **순서대로 하나씩** 만들기 때문에, 장면 수와 서버 성능에 따라 총 30초~2분 정도 걸릴 수 있습니다. `/shortform.html`에서는 기획안을 만든 뒤 "AI 추천 5개 만들기" 버튼을 누르면 이 결과가 카드 형태로 나오고, 각 카드의 "이 스타일로 최종 영상 만들기"를 누르면 그 조합이 자동으로 선택된 채로 최종 렌더링 패널로 이동합니다.

#### 배경음악 자동 추천 (`/api/shortform/bgm-suggestions`)

```
POST /api/shortform/bgm-suggestions
Body: { "scenes": [...] }   ← 1단계 응답의 scenes 배열
→ { "note": "...", "tracks": [ { "id": "calm-piano", "label": "잔잔한 피아노풍", "description": "...", "previewUrl": "/bgm/calm-piano.mp3", "score": 2 }, ... 5개 ] }
```

`assets/bgm/`에 있는 **우수리미가 직접 합성해서 만든(저작권 걱정 전혀 없는) 심플 배경음 5종** — 신나는 팝 / 잔잔한 피아노풍 / 감성 브이로그 / 트렌디 힙합비트 / 밝은 어쿠스틱풍 — 중에서, 대본(scenes의 caption) 안에 들어있는 키워드를 보고 어울리는 순서로 정렬해서 5개 전부를 돌려줍니다. 외부 음원 사이트에서 가져온 게 아니라 `scripts/generate-bgm.js`가 ffmpeg 사인파 합성으로 직접 만든 짧은 루프라서, 상업적으로 써도 저작권 문제가 없습니다(다만 진짜 악기로 녹음한 음악만큼 풍부한 소리는 아닙니다 — 더 퀄리티 높은 음원을 쓰고 싶으면 `bgm` 필드로 직접 mp3를 업로드하세요).

#### 켄번즈(확대·축소) 애니메이션

정지된 사진이 밋밋해 보이지 않도록, 장면마다 ffmpeg의 `zoompan` 필터로 천천히 확대되거나 축소되면서 살짝 좌우로 이동하는 효과를 자동으로 넣습니다(장면 번호에 따라 확대/축소, 팬 방향이 번갈아 적용되어 매 장면이 조금씩 다르게 보입니다). `animate=false`를 보내면 이 효과 없이 정지 사진으로 만듭니다.

#### 사진 프레임 스타일 — 포토카드(폴라로이드) / 화면 꽉 채우기 (`/api/shortform/frame-styles`)

사용자가 보내주신 캡컷 예시 영상(요즘 흔히 쓰는 "하얀 테두리 카드 + 배경은 같은 사진을 흐리게 확대해서 채우는" 스타일)에 맞춰 새로 추가한 옵션입니다. `frameStyle: "polaroid"`(기본값)를 주면, 사진을 하얀 테두리(사방 20px)를 두른 카드 형태로 화면 중앙에 배치하고, 그 뒤 배경은 같은 사진을 화면 전체 크기로 크게 확대한 뒤 블러(흐림) + 살짝 어둡게 처리해서 채웁니다. 카드 뒤에는 은은한 그림자(반투명 검은 박스를 블러 처리)도 함께 넣어서 입체감을 줍니다. `frameStyle: "full"`을 주면 예전처럼 사진이 화면 전체를 꽉 채우는 스타일로 만들어집니다(사진 안에 이미 표/인포그래픽처럼 여백 없이 꽉 찬 정보가 있을 때는 이 스타일이 더 잘 어울릴 수 있습니다). `/shortform.html`의 "영상 파일(mp4)로 만들기" 패널에 드롭다운으로 선택할 수 있게 넣어뒀습니다.

```
GET /api/shortform/frame-styles
→ { "frameStyles": [ { "id": "polaroid", "label": "포토카드(폴라로이드)", "description": "..." }, { "id": "full", "label": "화면 꽉 채우기", "description": "..." } ] }
```

**⚠️ 정직하게 밝혀두는 한계**: 이 기능은 어디까지나 "사용자가 고른 사진"을 재료로 카드/애니메이션을 자동 합성하는 것이지, 사람이 직접 들고 촬영한 셀카·손 움직임·카메라 각도 변화가 담긴 **실제 촬영 영상 그 자체**를 새로 만들어내는 건 아닙니다. 참고해주신 예시 영상 중 실제 매장에서 손으로 폰/태블릿을 들고 찍은 라이브 영상(사람이 움직이는 진짜 촬영본)은 "사진 슬라이드 자동화" 도구의 범위를 벗어나서 그대로 재현할 수는 없고, 정지 사진들을 포토카드 스타일로 부드럽게 이어붙이는 것까지가 이 기능이 할 수 있는 범위입니다.

#### 장면 전환 — 크로스페이드(xfade/acrossfade)

예전에는 장면마다 각자 검은 화면으로 페이드 인/아웃을 넣고 그냥 순서대로 이어 붙여서(하드컷), 장면이 바뀔 때마다 살짝 어두워졌다 밝아지는 느낌이었습니다. 지금은 영상 맨 처음과 맨 끝에만 그 페이드를 남기고, 장면과 장면 사이는 ffmpeg의 `xfade`(화면)와 `acrossfade`(소리) 필터로 0.35초 동안 부드럽게 겹쳐서 넘어가도록 바꿨습니다 — 캡컷 등에서 흔히 보는 "디졸브" 전환과 비슷한 느낌입니다. 이 크로스페이드 합성이 어떤 이유로(예: ffmpeg 빌드 문제) 실패하면, 영상 자체가 안 만들어지는 것보다는 낫다고 보고 예전 하드컷 방식으로 자동 대체됩니다.

#### QR 코드로 휴대폰 전송

영상이 완성되면, 그 mp4의 실제 인터넷 주소(`videoUrl`)를 `qrcode` 패키지로 QR 이미지(base64 data URL)로 만들어서 같이 내려줍니다. `/shortform.html`에서는 영상 아래에 이 QR 이미지가 바로 표시되니, 휴대폰 카메라로 찍으면 컴퓨터↔휴대폰 사이에 파일을 옮길 필요 없이 바로 그 주소로 들어가서 다운로드할 수 있습니다.

## AI 자동화 글쓰기 (`/blog-writer.html`)

카테고리 8종(맛집 후기/여행 후기/정보성 글/소개·홍보글/IT·상품리뷰/비즈니스·경제/뷰티·패션/일상·취미) 중 하나를 드롭다운에서 고르면 **실시간 트렌드 주제**를 보여주고, 주제를 고르거나 직접 입력한 뒤 **"🖥️ 클로드 앱에서 글 생성하기"** 버튼을 누르면, 그 카테고리에 맞는 스킬이 채워진 채팅창으로 데스크톱 클로드 앱이 열립니다.

```
GET  /api/blog/categories   → 카테고리 목록(각 항목에 claudeAppTriggerTemplate 포함)

```

**트렌드 주제는 진짜 데이터입니다** — "정보성 글"은 구글 트렌드 대한민국 실시간 인기 검색어(공식 공개 RSS) + 네이버 검색 데이터 기반 사회·시사 "기회 키워드", 나머지 7개는 네이버 검색 데이터 기반 "기회 키워드"(황금 키워드 찾기와 같은 로직)를 씁니다. 다만 "소개/홍보글"은 정확히 맞는 시드 키워드가 없어서, 없는 데이터를 지어내는 대신 뜻이 가장 가까운 분야(인테리어·DIY, 원예·재배)로 대신 채웠고 화면에도 그 사실을 그대로 안내합니다.

### 🖥️ 이전 버전(서버 Claude API 초안 생성)에서 클로드 앱 연동으로 전환

원래는 "초안 생성하기"를 누르면 서버에 등록된 Claude API 키로 제목·본문을 생성했지만, API 종량제 비용 부담 때문에 사장님 요청으로 방식을 바꿨습니다. 이제는 서버 API를 전혀 거치지 않고, 카테고리별로 사장님이 claude.ai 계정에 저장해두신 스킬을 그대로 활용합니다.

```
food_review    → {topic} 맛집 후기 블로그 써줘        (새로 만든 food-review 스킬)
travel_review  → {topic} 여행 후기 블로그 써줘        (새로 만든 travel-review 스킬)

intro_promo    → {topic} 소개 홍보 블로그 써줘        (새로 만든 intro-promo 스킬)
it_review      → {topic} IT 자동차 블로그 써줘        (기존 it-auto 스킬)
biz_economy    → {topic} 재테크 경제 블로그 써줘      (기존 wealth-life 스킬)
beauty_fashion → {topic} 블로그 써줘                  (연예인 패션/패션 후기/연예인 뷰티/뷰티 후기 4개 중 클로드가 주제 내용을 보고 자동 선택)
```

food-review/travel-review/intro-promo 3개는 이 프로젝트에 정확히 맞는 기존 스킬이 없어서, 가장 가까운 living-life(리빙 라이프) 스킬의 구조(0~7단계, 제목 45~50개·16종 후킹 장치, 정보 박스, 팩트체크, 이미지 프롬프트 등)를 그대로 가져와 각 도메인에 맞게 새로 작성했습니다. `.skill` 파일로 따로 전달드렸으니 claude.ai 계정에 저장해 주세요.

**⚠️ 클로드 앱 딥링크의 한계**: `claude://claude.ai/new?q=...` 형태의 딥링크는 입력창에 문구를 미리 채워주는 것까지만 지원하고, 자동 전송(submit)은 지원하지 않습니다(Anthropic 공식 문서 기준). 그래서 앱이 열리면 채팅창에 문구가 채워져 있는 걸 확인하고 전송 버튼을 한 번 눌러야 스킬이 실제로 작동합니다. 또한 이 딥링크는 데스크톱 클로드 앱 전용이라 모바일·웹 브라우저에서는 안 열릴 수 있습니다.

## 맞춤형 글쓰기 프롬프트 (`/prompt-studio.html`)

"머니대외비" 같은 사이트의 글쓰기프롬프트 화면처럼, 역할별로 미리 짜둔 프롬프트를 카드로 모아두고 "챗봇 사용하기"를 누르면 바로 대화할 수 있는 화면입니다. 다만 그 사이트들이 카드마다 ChatGPT의 커스텀 GPTs나 Gemini Gem 같은 **외부 챗봇 서비스**로 연결하는 것과 달리, 여기서는 이 프로젝트에 이미 연동해 둔 **Claude API를 그대로 재사용**해서 카드마다 별도 가입이나 키 발급이 필요 없습니다.

```
GET  /api/prompt-studio/tools                → 카드(챗봇) 목록
POST /api/prompt-studio/run
  Body: { "toolId": "google-seo", "messages": [ { "role": "user", "content": "..." }, ... ] }
  → { "reply": "..." }
```

`messages`는 그 카드 안에서 이어지는 대화 기록을 그대로 보내는 방식이라, 한 카드 안에서 "조금 더 짧게 다시 써줘" 같은 후속 요청도 가능한 멀티턴 챗봇처럼 동작합니다.

**"이미지 생성기" 카드는 실제 이미지 파일을 만들지 않습니다** — 이 프로젝트에는 이미지 생성 AI가 직접 연동되어 있지 않아서, 대신 이미지 생성 AI에 붙여넣을 수 있는 **프롬프트 문구**(일러스트 버전 + 사실적인 사진 버전)를 만들어줍니다. 카드에는 **🎬 Google Flow에서 이미지 만들기** 버튼이 있어서, 눌러보면 [구글 Flow 공식 사이트](https://labs.google/fx/tools/flow)를 새 창으로 열어드립니다 — 그 화면에서 생성된 프롬프트를 붙여넣기(Ctrl+V) 하면 실제 이미지가 만들어져요. 왜 완전 자동으로 이미지까지 만들어주지 않는지 이유를 말씀드리면: 구글 Flow는 외부 개발자가 쓸 수 있는 **공식 API가 없습니다**. `useapi.net` 같은 비공식 서비스가 있긴 하지만, 사용하려면 사장님의 실제 구글 계정 로그인 쿠키를 그 회사 서버에 직접 넘겨야 해서 계정 정지·보안 위험이 있어 만들어드리지 않았습니다(네이버 블로그 자동 발행 때와 같은 이유입니다). 완전 자동으로 진짜 이미지 파일까지 만들고 싶으시면, 구글이 공식으로 제공하는 **Gemini API의 이미지 생성 모델**(Nano Banana 계열, `gemini-3.1-flash-image` 등 — Flow가 내부적으로 쓰는 것과 같은 계열의 모델을 공식 API로 쓰는 방식)을 새로 연동하는 방법이 있습니다. 이 경우 `GEMINI_API_KEY` 발급과 사용량만큼의 별도 비용이 필요해서, 진행 여부는 말씀해 주시면 다음 단계로 연동해 드릴게요.

18개 카드 전부 Claude API(`ANTHROPIC_API_KEY`)가 필요하고, 키가 없으면 "이 챗봇을 쓸 수 없다"는 안내만 나오고 서버는 죽지 않습니다.

### 🖥️ "클로드 앱에서 열기" 버튼

각 카드에는 **🖥️ 클로드 앱에서 열기** 버튼이 있습니다. 데스크톱에 설치된 클로드 앱을 `claude://claude.ai/new?q=...` 딥링크로 열어서, 그 카드의 지침이 미리 채워진 새 대화창을 띄워드립니다.

**⚠️ 정직하게 밝혀둘 기술적 한계**

- 이 딥링크는 **데스크톱 앱 전용 공식 기능**입니다(모바일 앱·웹에서는 지원되지 않을 수 있어요). 클로드가 특정 "스킬"을 강제로 실행시키는 공식 딥링크 방식은 따로 없습니다 — 스킬은 대화가 시작된 뒤 메시지 내용을 보고 클로드가 알아서 매칭하는 방식입니다.
- **원문 지침 자체가 짧은 카드**(이미지 생성기, 썸네일 문구, 카드뉴스 문구, 쓰레드 요약본, 쇼핑커넥트, 드라마 생성기 6개)는 그 지침 전체를 대화창에 미리 채워 넣습니다.
- **원문이 아주 긴 "클로드 스킬" 기반 카드**(방송이슈·연예인 가십·연예인 패션·골든 패션 후기·연예인 뷰티·골든 뷰티 후기·재테크·경제·리빙·라이프·스포츠 이슈·건강 정보·교육·지식·심리·IT·자동차)는 원문이 최소 몇천 자~7만 자에 달해서 딥링크에 통째로 넣을 수 없습니다(딥링크는 텍스트를 URL로 인코딩해서 전달하는데, 특히 한글은 인코딩하면 글자당 9자로 부풀어서 실제 담을 수 있는 분량이 매우 작습니다). 그래서 이 카드들은 **"방송 이슈 블로그 써줘"처럼 짧은 트리거 문구만** 전달합니다 — 그 스킬이 사장님 클로드 계정에 실제로 저장되어 있어야, 클로드가 문구를 보고 그 스킬을 자동으로 골라 씁니다. (연예인 패션/골든 패션 후기/연예인 뷰티/골든 뷰티 후기는 이미 계정에 저장되어 있다고 하셨고, 방송 이슈·연예인 가십·재테크·경제·리빙·라이프·스포츠 이슈·건강 정보·교육·지식·심리·IT·자동차는 이 프로젝트가 만들어 드린 `.skill` 파일을 계정에 저장하셔야 정상 동작합니다.)
- 프리필만 될 뿐 **자동으로 전송되지는 않습니다** — 열린 채팅창에서 직접 전송 버튼을 눌러야 해요.

### 🔑 "황금 키워드 찾기"와 같은 기능인가요?

**핵심 아이디어는 같습니다.** 첨부해 주신 "머니대외비"의 "황금키워드" 기능과 이 프로젝트의 `/opportunity.html`(`/api/opportunity`)은 둘 다 "검색은 많은데 블로그 글은 적은 틈새 키워드"를 찾는다는 같은 원리(검색량 ÷ 문서 수)를 씁니다. 다만 세부적으로는 조금 다릅니다.

- **머니대외비**: 네이버·네이트·줌·구글·다음 5개 플랫폼의 실시간 급상승 검색어를 한 화면에서 비교해서 보여주고, 키워드 리포트에 T(트래픽 수요)·C(광고주 수요)·D(지속 가능성)·N(경쟁 포화도) 4가지 참고 점수를 매기고, 쇼핑키워드/애드센스키워드 탭이 별도로 있고, 사용자가 직접 자기 API 키를 등록해서 쓰는 방식(BYOK)입니다.
- **이 프로젝트**: 네이버 검색광고 키워드도구 + 네이버 블로그 검색 API로 같은 원리(검색량 ÷ 문서 수)의 점수를 계산하고, 카테고리 16종(패션/미용, 국내여행, 반려동물 등)으로 미리 나눠서 보여주며, 서버에 등록된 API 키를 모든 방문자가 함께 씁니다. 실시간 급상승어는 구글 트렌드 대한민국 RSS 하나만 쓰고 있습니다("AI 자동화 글쓰기"의 "네이버 홈판 유력" 카테고리에서 사용 중).

즉 **다른 서비스가 아니라 같은 종류의 기능을 이미 갖고 계신 것**이고, 원하시면 (1) 네이트·줌·다음까지 실시간 급상승어를 더 붙이거나, (2) T/C/D/N 같은 참고 점수 UI를 추가하거나, (3) 쇼핑/애드센스 전용 탭을 나누는 식으로 `/opportunity.html`을 머니대외비 스타일에 더 가깝게 다듬을 수 있습니다 — 필요하시면 다음 단계로 요청해 주세요.

## 홈판 벤치마킹 블로거 리스트 (`/benchmark.html`)

사장님이 보내주신 "8월 4기 홈판 벤치마킹 블로거 리스트" 노션 페이지 스크린샷 13장을 그대로 옮겨 만든 정적 참고 페이지입니다. 카테고리(IT/자동차·재테크 라이프·연예인 가십·연예인 패션·방송 이슈·리빙 라이프·건강 상식·스포츠·교육/지식/심리 + 이후 직접 알려주신 뷰티/패션 벤치마킹 블로거 주소)별로 닉네임·링크·일평균 방문자·추천 포인트를 표로 정리했고, 홈판 벤치마킹 사이트 리스트(포털·언론사·커뮤니티 트렌드 링크)와 네이버 블로그 방문자 랭킹 TOP 100(26년 7월·8월)도 함께 들어 있습니다.

**⚠️ 정직하게 밝혀둘 점**

- 실시간으로 방문자 수·순위를 다시 조회하는 기능이 아닙니다 — 스크린샷 속 숫자를 그 시점 그대로 옮긴 정적 페이지입니다.
- 스크린샷에서 "blog.naver.com"처럼 링크 글자만 보이고 실제 주소가 하이퍼링크 뒤에 가려져 있던 항목은, 정확한 블로그 아이디를 알 수 없어서 **클릭 안 되는 텍스트로만** 남겨뒀습니다(추측해서 지어 넣지 않았습니다). 이후 사장님이 직접 정확한 주소 목록(8월 메이트 뷰티/패션 블로거 등)을 알려주신 건 실제 링크로 반영했고, 겹치는 닉네임(예: 이잼챙→이잼잼, 페님→쪠님)은 오타를 바로잡았습니다.
- 네이버 블로그 방문자 랭킹 TOP 100은 **26년 6월 스크린샷을 받지 못해서 이 페이지에 없습니다.** 7월·8월도 노션 화면에 "더 불러오기" 전까지만 보였던 상태라 100개 전체가 아니라 스크린샷에 보인 만큼만 들어 있습니다(작은 글씨를 100줄 넘게 옮겨적다 오타가 날 위험이 있어서, 이 두 랭킹표는 직접 옮겨 적는 대신 스크린샷 원본 이미지를 그대로 붙여넣었습니다).

## 다른 소스 추가하기

`src/trendSource.js`처럼 `{ source, fetchedAt, items }` 형태를 반환하는 함수를 하나 더 만들고, `src/index.js`의 `refresh()`에서 같이 호출해 `cache`에 별도 키로 저장하면 됩니다. 다음(Daum) 실시간 인기 검색어나 줌(ZUM) AI 이슈 트렌드처럼 공식 RSS/API가 열려 있지 않은 소스는 스크래핑이 필요한데, 이용약관 검토와 차단 대응(User-Agent, 요청 간격 조절 등)이 별도로 필요합니다.

## 제공하지 않는 것

- **"지금 이 순간 뜨는 검색어 순위" 그 자체** — 네이버는 2021년에 이 기능을 완전히 폐지했고, 공식 API로도 다시 제공하지 않습니다. 대신 검색량(키워드도구)과 경쟁 정도(블로그검색)를 조합한 "기회 키워드"로 실질적인 대안을 제공합니다.
- 초 단위 실시간 스트리밍 (모든 트렌드 API는 결국 몇 분 간격의 배치 갱신입니다)
- 인증/과금/속도 제한 (실제 서비스로 공개하려면 최소한의 rate limiting을 추가하는 걸 권장합니다)
- 네이버 API 자체의 하루 호출 한도 관리 (검색광고 API·오픈 API 모두 일일 호출 한도가 있습니다 — 트래픽이 늘면 캐시 시간을 늘리거나 유료 한도 상향을 검토하세요)
